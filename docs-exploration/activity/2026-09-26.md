# Activity Log (2026-09-26)

This log summarizes key development themes, notable merges, and maintainer requests in the Agent Substrate repository over the past two weeks (September 12, 2026 to September 26, 2026).

## Themes of the Window

The primary focus of this window has been a major architectural evolution: migrating Agent Substrate from a **single-actor-per-worker** model to **multi-actor worker support**. Previously, worker pods (each running an `ateom` process) hosted at most one actor at a time, hard-coding worker capacity to 1 and preventing resource sharing. In the last two weeks, a sequence of critical PRs successfully decoupled networking, storage directories, and cgroups per sandbox, allowing workers to density-host up to 1000 sandboxed actors concurrently.

Alongside this structural density shift, developers have focused heavily on **dataplane path decoupling** and **database logic modularization**. Giant monolithic codebases like `internal/ateompath` and `cmd/ateapi/internal/store/atepg/atepg.go` have been broken down into decoupled, clean, single-responsibility files. Network and credential integration (including Kubernetes secret-backed credential providers) has also matured to prepare for production readiness.

## Notable Merges

1. **Multi-Actor Worker Support (#1836):**
   This landmark change addresses long-term density and performance limits. It introduces `hosted.go` into both `ateom-gvisor` and `ateom-microvm` to track and run multiple independent actor sandboxes under a single worker pod. It leverages individual actor locks, isolated network namespaces, and nested cgroups to keep hosted workloads secure.

2. **Per-Sandbox Networking (#1689):**
   A strict prerequisite for multi-actor workers, this PR decouples the worker pod network namespace from the hosted actor's sandbox. Each sandbox now receives its own isolated network namespace (`netns`), `veth` interfaces, and custom iptables rules for secure, independent routing.

3. **Path Decoupling & ActorDirs Message (#1730):**
   Previously, both `atelet` and `ateom` shared the exact same code path in `internal/ateompath` to compute per-actor directories. This PR split `ateompath` into `ateletpath` (private to the node daemon), `nodepath` (for basic cross-component mount points), and introduced the `ActorDirs` protobuf message to carry computed paths over RPC, decoupling the components.

4. **Modular PostgreSQL Store (#1777):**
   Split the monolithic `atepg.go` (and its test counterpart) into individual, resource-specific files under `cmd/ateapi/internal/store/atepg/` (e.g., `actor.go`, `worker.go`, `tag.go`, `egress_policy.go`). This greatly improves codebase navigability and prevents git merge conflicts on store files.

5. **RevertActor Lifecycle RPC (#1675):**
   Introduced a new public control plane lifecycle RPC (`RevertActor`) to allow rolling back a running or crashed actor's state to its last known healthy snapshot, with full support throughout workflows and the databases.

## Where the Churn is Concentrated

- **Node Dataplane (`cmd/ateom-gvisor`, `cmd/ateom-microvm`, `cmd/atelet`):** High churn to implement multi-actor hosting, cgroups, process-safety/cleanup for hanging VM/sandbox processes, and path decoupling.
- **API Control Store (`cmd/ateapi/internal/store/atepg/`):** Complete structural refactor of the PostgreSQL database backend.
- **Telemetry & Logging (`internal/actorevent`, `internal/otlprelay`):** Shift towards routing multi-actor lifecycle and resource-usage metrics over OTLP relays and files.

## What Returning Contributors Must Know

- **Single-Actor Limits are Gone:** Workers can now run up to 1000 actors simultaneously (controlled by the `--max-actors` flag). All code assuming a 1:1 worker-to-actor mapping must be updated.
- **Do Not Modify `ateompath` unadvised:** Shared path resolution is moving to the protobuf-based RPC (`ActorDirs`). Ensure you check `internal/nodepath` and `ateletpath` before modifying path code.
- **Postgres Store Files are Modular:** If you need to update a PostgreSQL schema or query, look inside the individual resource files (e.g., `actor.go`, `worker.go`) inside `cmd/ateapi/internal/store/atepg/` rather than a monolithic `atepg.go`.
